# BRO1310: Field names should not use Hungarian notation

Variable, parameter and field names don't start with a type prefix: `count`, not `iCount`. Replaces StyleCop
**SA1305**. Off by default, like StyleCop's.

## Example

```ini
root = true

[*.cs]
dotnet_diagnostic.BRO1310.severity = warning
```

### Before

```csharp
public class Order
{
    private int nItems;

    public string Describe(string szCustomer, bool isPaid)
    {
        var strTotal = nItems.ToString();
        return szCustomer + ": " + strTotal + (isPaid ? " (paid)" : string.Empty);
    }
}
```

### After

```csharp
public class Order
{
    private int items;

    public string Describe(string customer, bool isPaid)
    {
        var strTotal = items.ToString();
        return customer + ": " + strTotal + (isPaid ? " (paid)" : string.Empty);
    }
}
```

## Why

A prefix repeats the type, which the compiler and the editor already know, and goes stale when the type changes.

## Configuration

```ini
# Prefixes that are fine (StyleCop's allowedHungarianPrefixes).
stylebro_allowed_hungarian_prefixes = db, ui

# StyleCop's list of common words that look like prefixes (as, at, by, do, go, if, in, is, it, no, of, on, or, to)
# is allowed unless this is false (allowCommonHungarianPrefixes).
stylebro_allow_common_hungarian_prefixes = true
```

`stylebro-migrate` writes both from `stylecop.json`.

## How the fix works

A prefix is what StyleCop counts as one: one or two lower-case letters followed by an upper-case letter (`iCount`,
`szName`; `strName` has three letters and isn't one). The fix removes it and lowers the rest like
[BRO1301](BRO1301.md): `pURL` becomes `url`. It's the same rename as the other naming rules, with the same safety
checks, so `_iCount` gets one rename to `count` (or `_count` with `stylebro_private_field_naming = _camelCase`),
reported as BRO1310.

## Not reported

- **Classes whose name ends in `NativeMethods`**, like StyleCop: Win32 names (`lpBuffer`, `dwFlags`) stay.
- **Parameters that keep a base method's or interface's name, record parameters, partial methods**, like
  [BRO1302](BRO1302.md).
- **Constants, `static readonly`, public and internal fields:** they are PascalCase ([BRO1306](BRO1306.md)), so
  `xPos` becomes `XPos` there and no longer has a prefix.
- **Another name in the member would get the same new name:** `xItem` and `yItem` in one query, or a parameter
  `nSize` in a method named `Size`. Renaming one would collide with the other, or take two runs.
- **Any case the other naming rules skip** (the new name is taken, the name appears in a string, ...).

## Compared with StyleCop

StyleCop has no fix for SA1305. It reports constant, static readonly and public fields too; StyleBro reports those
as [BRO1306](BRO1306.md) and renames them to PascalCase, which also removes the prefix's lower-case form. StyleCop
doesn't look past a leading underscore (`_iCount`), but once SA1309 removes it SA1305 reports `iCount`; StyleBro
reports `_iCount` right away and renames it once.
