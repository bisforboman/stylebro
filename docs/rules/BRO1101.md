# BRO1101: Code should not contain empty statements

Replaces StyleCop **SA1106**.

Reports a `;` that does nothing:

- an empty statement in a block or a `case` section: `M(); ;`, or a line with only `;`
- a `;` after the closing brace of a type or namespace: `class C { };`

## Code fix

Removes the `;`. A line that held only the `;` is removed completely; otherwise the `;` goes with the space in front
of it (`M(); ;` becomes `M();`). A `;` at the start of a line takes the space after it instead, so `; // done`
becomes `// done` at the same indentation.

## Not reported

- **Embedded empty statements**, such as `while (Poll()) ;` or `if (x) ;`. StyleCop turns these into `{ }`, which
  keeps the behavior but hides what is often a bug. The compiler already warns about the suspicious ones
  (CS0642, "Possible mistaken empty statement"), and an automatic fix would silence that warning.
- **Labeled empty statements** (`end: ;`). A label needs a statement, so removing the `;` can break the build when
  the label is the last thing in a block.
- **A record without a body** (`record R(int X);`), where the `;` is required.
