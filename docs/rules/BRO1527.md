# BRO1527: Auto-accessors should be on one line

A property or indexer whose accessors are all auto-accessors (`get;`, `set;`, `init;`, also with a modifier such as
`private set;`) goes on one line: `public int Simple { get; set; }`. Not a StyleCop rule: from Roslynator's
[RCS0042](https://josefpihrt.github.io/docs/roslynator/analyzers/RCS0042).

## Example

### Before

```csharp
public class Person
{
    public string Name
    {
        get;
        set;
    }

    public int Age
    {
        get;
        private set;
    } = 18;
}
```

### After

```csharp
public class Person
{
    public string Name { get; set; }

    public int Age { get; private set; } = 18;
}
```

## Why

The one-line form is how auto-properties are written almost everywhere; spread over five lines they look like a
property with logic. The SDK's IDE0360 (`get { return field; }` -> `get;`, in `stylebro-migrate init --modernize`)
leaves the accessors on their old lines; this rule finishes the job.

## How the fix works

The whitespace from the declaration's name to the `{`, between the accessors and before the `}` becomes one space each.
An initializer (`= 18;`) stays after the `}`. When the multi-line property needed a blank line next to it that a
one-line property doesn't ([BRO1505](BRO1505.md) between properties, or [BRO1519](BRO1519.md) after the `}` when BRO1505
is off), the fix adds it, so the result doesn't depend on which fix `dotnet format` runs first.

One case still depends on the order: when [BRO1001](BRO1001.md) sorts the multi-line property next to a one-line
property, it adds the blank line BRO1505 wants there if it runs first, and none if this fix ran first. Both results
are clean and a second run changes nothing.

IDE0360's fix runs in `dotnet format`'s code-style pass, before the analyzer pass with this rule, so a property it
shortens is put on one line in the same run, and IDE0360 doesn't touch the result. They don't fight.

## Not reported

- An accessor with a body (`get { ... }`), an expression body (`get => x;`) or an attribute (`[Obsolete] get;`).
- A comment or directive anywhere from the declaration's name to the `}`, or a line break inside an accessor.
- An initializer that doesn't start on the `}` line.
- `csharp_preserve_single_line_blocks = false` in `.editorconfig`: the SDK's formatter (IDE0055) would expand the list
  again. The preset sets it to `true`.

A long line isn't split or avoided: the one-line form is as long as the declaration plus the accessors.

## Compared with StyleCop

StyleCop has no such rule (SA1502 allows `{ get; set; }` on one line but doesn't ask for it). `stylebro-migrate` turns
it off (see [Rules beyond StyleCop](../differences-from-stylecop.md#rules-beyond-stylecop)).
