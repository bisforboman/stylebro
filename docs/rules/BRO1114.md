# BRO1114: Do not combine fields

Every field (and event field) has a declaration of its own. Replaces StyleCop **SA1132**.

## Example

### Before

```csharp
using System;

public class Point
{
    private int x, y;

    [Obsolete("Use Label.")]
    public string name = string.Empty, title = string.Empty;
}
```

### After

```csharp
using System;

public class Point
{
    private int x;
    private int y;

    [Obsolete("Use Label.")]
    public string name = string.Empty;
    [Obsolete("Use Label.")]
    public string title = string.Empty;
}
```

## Why

A combined declaration hides the second field at the end of a line, and a change to one field's type or modifiers
changes all of them.

## How the fix works

Each field gets its own declaration with the same attributes, modifiers and type, and the same documentation comment
if there is one, in the same order (initializers keep running in the same order). Event fields, and a field that spans
several lines from the next, are separated by a blank line, which [BRO1505](BRO1505.md) wants between them. A
documented field's copies are too, which [BRO1513](BRO1513.md) wants above each documentation comment. Local variables (`int a, b;` in a method) aren't reported, like
in StyleCop.

## Not reported

- **A comment inside the declaration** (`int a, /* note */ b;`).
- **A declaration that shares its first line with other code.**

## Compared with StyleCop

Same positions as StyleCop. Under `dotnet format` StyleCop's fix also copies the attributes and the documentation
comment to every field (measured 2026-11-07 on 1.2.0-beta.556 and 1.3.177-beta; this page said before that it kept
them on the first field only).
