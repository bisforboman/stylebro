# BRO1008: Using directives should be placed correctly

Using directives go inside or outside the namespace, as `csharp_using_directive_placement` says. Replaces StyleCop
**SA1200**, and the SDK's IDE0065, whose fix can break the build.

## Example

```ini
[*.cs]
csharp_using_directive_placement = outside_namespace
```

### Before

```csharp
namespace Shop.Orders
{
    using System;
    using System.Collections.Generic;

    public class Order
    {
        public List<DateTime> Changes { get; } = new();
    }
}
```

### After

```csharp
using System;
using System.Collections.Generic;

namespace Shop.Orders
{
    public class Order
    {
        public List<DateTime> Changes { get; } = new();
    }
}
```

## Why

One place for usings in every file. Where they are also decides how names are looked up: inside the namespace, a
using's names come before the enclosing namespaces' members; outside, after them.

## How the fix works

All usings of the file move together, and only when every name in the file still binds to the same symbol afterwards
(types, members, extension methods, query clauses, `foreach`, `await`, collection initializers, deconstruction, and
the usings' own targets), with no new compile errors. The SDK's IDE0065 fix doesn't check that: in eShop it made
`Order` ambiguous (CS0104), in Ocelot a type name turned into a namespace (CS0118). When the check fails, nothing is
reported.

- Comments directly above the first using move with it; the file header stays on top.
- Outside: the usings go above the namespace (and the comments directly above it), with a blank line before the
  namespace and none at the start of the file. Relative names get their full name, like
  [BRO1126](BRO1126.md)'s fix (`using IO;` inside `namespace System` becomes `using System.IO;`).
- Inside: below `{` (indented one level), or below `namespace X;` after a blank line, with a blank line before
  what follows.
- In a multi-targeted project every target framework's copy of the file must agree; otherwise the warning stays.

## Configuration

```ini
[*.cs]
# The SDK's setting (StyleCop's usingDirectivesPlacement):
#   inside_namespace (or not set: StyleCop's default), outside_namespace
#   anything else (preserve): nothing is reported
csharp_using_directive_placement = outside_namespace
```

The preset sets `outside_namespace`.

## Not reported

- **Files where a name would bind differently** with the usings moved (see above).
- **Files with more than one namespace**, with types, attributes or top-level statements outside the namespace,
  with usings on both levels, global usings, or extern aliases.
- **A directive** (`#if`, `#pragma`, `#nullable`, ...) anywhere before the namespace's body.
- **A using sharing its line** with other code.
- With `inside_namespace`, a file without a namespace (StyleCop reports its usings, but there's nowhere to move them).

## Compared with StyleCop

Same positions and output where both report (parity sets `using-placement` and `using-placement-outside`), except
that StyleCop's fix drops the blank line below `namespace X;`. StyleCop's fix moves usings without checking what they
bind to: in the parity sets it turned `Order` into another type, and produced code that doesn't compile (CS0234).
