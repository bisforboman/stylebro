# BRO1001: Members should be ordered

Replaces StyleCop **SA1201, SA1202, SA1203, SA1204 and SA1214**.

Members of a class, struct, record or interface are sorted by these keys, in this order:

1. **Kind**: field, constructor, finalizer, delegate, event, enum, interface, property, indexer, conversion, operator, method, struct, class
2. **Accessibility**: public, internal, protected internal, protected, private protected, private
3. **Constants** before other fields
4. **Static** before instance
5. **Readonly** fields before mutable fields

Members with equal keys keep their existing relative order.

## Configuration

```ini
[*.cs]
stylebro_member_order = field, constructor, property, method
stylebro_member_access_order = public, internal, protected, private
stylebro_member_constants_first = true
stylebro_member_static_first = true
stylebro_member_readonly_first = true
```

Kinds and accessibilities you leave out keep their default relative order, after the ones you list.
`conversion` means conversion operators (`implicit operator`/`explicit operator`); `operator` means all other operators.

## Code fix

The fix sorts the whole type. Blank-line layout stays in place, while comments, XML docs and attributes move with their member. Fix All sorts nested types first, so one `dotnet format` run is enough:

```
dotnet format analyzers --diagnostics BRO1001
```

If the project uses `TreatWarningsAsErrors`, don't exempt the rule with `<WarningsNotAsErrors>BRO1001</WarningsNotAsErrors>`:
`dotnet format` then skips BRO1001 entirely and fixes nothing, although the build still reports it. Set the severity in
`.editorconfig` instead (`dotnet_diagnostic.BRO1001.severity = suggestion`), or run `dotnet format` before building.

## Not reordered

Types with preprocessor directives between members (`#region`, `#if`, `#pragma`) are skipped. Reordering could break the scope of those directives.

Types where sorting would change what field initializers compute are skipped too. Initializers run in source order,
so in this class moving `B` above `A` (readonly first) would make `B` 1 instead of 6:

```csharp
public static class C
{
    public static int A = 5;
    public static readonly int B = A + 1;
}
```

A type is skipped when sorting would swap two static initializers, or two instance initializers, and either of them
mentions a member of the type (directly or through a method), or creates an instance of the type (`new()` in a singleton).
`typeof`, `nameof` and names on other objects (`text.Length`) don't count. Side effects outside the type, such as
two initializers calling the same external counter, aren't detected.
