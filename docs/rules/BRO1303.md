# BRO1303: Private field names should be camelCase

Private fields are named `count`, or `_count` if you configure that style. Replaces StyleCop **SA1306** and
**SA1309** for private fields.

## Example

### Before

```csharp
public class Account
{
    private decimal _balance;
    private readonly string Owner;

    public Account(string owner, decimal balance)
    {
        Owner = owner;
        _balance = balance;
    }

    public string Describe() => Owner + ": " + _balance;
}
```

### After

```csharp
public class Account
{
    private decimal balance;
    private readonly string owner;

    public Account(string owner, decimal balance)
    {
        this.owner = owner;
        this.balance = balance;
    }

    public string Describe() => owner + ": " + balance;
}
```

## Why

One naming style for private fields makes them recognizable at a glance. The default, `count`, is StyleCop's; many
.NET codebases (including the .NET runtime) use `_count` instead, which keeps fields apart from parameters without
`this.`. Pick one with `.editorconfig`.

## Configuration

```ini
[*.cs]
# 'camelCase' (default): count. '_camelCase': _count.
stylebro_private_field_naming = _camelCase
```

With `_camelCase`, `count`, `Count` and `__count` all become `_count`.

Without `stylebro_private_field_naming`, the SDK's naming rules decide: a `dotnet_naming_rule` whose symbols cover
private fields (kind `field` or `*`, accessibility `private` or `*`, no required modifiers) with a camel-case style picks
`camelCase` (no prefix) or `_camelCase` (`required_prefix = _`); the lowest `priority` wins. With neither, the default is
`camelCase`. The preset doesn't set the key, so a naming rule in your `.editorconfig` takes effect;
`stylebro-migrate` writes it from your StyleCop setup.

```ini
[*.cs]
dotnet_naming_rule.private_fields.symbols = private_fields
dotnet_naming_rule.private_fields.style = underscore_camel
dotnet_naming_rule.private_fields.severity = warning
dotnet_naming_symbols.private_fields.applicable_kinds = field
dotnet_naming_symbols.private_fields.applicable_accessibilities = private
dotnet_naming_style.underscore_camel.required_prefix = _
dotnet_naming_style.underscore_camel.capitalization = camel_case
```

## How the fix works

The field is renamed everywhere, in every part of a partial type. Where a local or parameter with the new name would
hide the field, the reference is qualified: `this.balance = balance`, or `Account.instances` for a static field. The
new name drops leading underscores and lowers the leading capitals, like [BRO1301](BRO1301.md).

Checked: private fields, instance or static, readonly or not. Constants and `static readonly` fields are PascalCase
(StyleCop's SA1303 and SA1311), and internal and public fields are [BRO1306](BRO1306.md)'s.

Protected (and private protected) fields follow StyleCop's defaults: one that isn't readonly is camelCase (SA1306),
and a readonly one's casing isn't checked (StyleCop leaves it unchecked: SA1306 skips it and SA1304 defers to SA1307,
which checks public and internal fields only). A leading underscore (SA1309) is removed in the `camelCase` style and
kept in the `_camelCase` style, which doesn't add one to protected fields either.

## Not reported

The fix only renames when that can't change what the code does:

- **The type or a base type already has a member with the new name.**
- **Two fields would get the same new name** (`_count` and `Count`).
- **The field has attributes, or the type is `[Serializable]` or has a serializer attribute** (`[JsonObject]`,
  `[DataContract]`, `[MessagePackObject]`, `[ProtoContract]`, ...). Serializers can depend on field names.
- **Another member's name contains the field's name**, like `ShouldSerialize_count` or `_countSpecified`: conventions
  that pair members by name (Json.NET, XML serialization, data binding) would break.
- **The old name appears in a string in the type**, alone or inside a longer string: reflection (`GetField("_count")`),
  `[DebuggerDisplay("{_count}")]`.
- **The old name appears in code excluded by `#if`**, which can't be renamed reliably.
- **The field names an anonymous type member or tuple element by inference** (`new { _count }`).
- **One-letter prefixes** (`m_count`, `s_count`): StyleCop's SA1308, and `s_` is the .NET runtime's style for
  static fields.
- **Names without a camelCase form:** only underscores, or a keyword (`Class`).

## Reported but not fixed

**A field whose old name appears as a string anywhere in the solution** keeps its name, and the warning stays.
That's usually reflection from another project, like a test reading a private field
(`GetField("_blockedUntil", ...)`): the rename would still compile but fail at run time. Rename such a field by hand
and update the string, or suppress the warning for it. (Found in Polly, whose tests read two private fields this
way.)

## Compared with StyleCop

Same results as StyleCop for private and protected fields, except for the skipped cases above. SA1309 also covers
constants and public fields, which are [BRO1306](BRO1306.md)'s.
