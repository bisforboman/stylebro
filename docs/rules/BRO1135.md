# BRO1135: Integer literal suffixes should be upper case

The suffix of an integer literal is upper case: `1L`, `2U`, `3UL`. Not a StyleCop rule (requested in StyleCop issue
[#1563](https://github.com/DotNetAnalyzers/StyleCopAnalyzers/issues/1563); Sonar S818).

## Example

### Before

```csharp
public class Limits
{
    public const long Max = 100l;
    public const uint Mask = 0xFFu;
    public const ulong Big = 1ul;
}
```

### After

```csharp
public class Limits
{
    public const long Max = 100L;
    public const uint Mask = 0xFFU;
    public const ulong Big = 1UL;
}
```

## Why

A lower-case `l` looks like the digit `1`: `100l` reads as `1001`. The C# specification recommends `L`, and the
compiler warns about `l` (CS0078) but has no fix for it. `u` follows so that a suffix is written one way.

## How the fix works

Only the suffix's letters change (`ul`, `Ul` and `uL` become `UL`; `lu` becomes `LU`). Hex and binary literals work the
same way: their suffix letters can't be digits. [BRO1122](BRO1122.md), which replaces casts with suffixes, writes upper
case, so the two rules agree.

## Not reported

- **Real literals**: `1.5f`, `2d` and `3m` stay as they are, and so does the exponent's `e`. Lower case is the common
  way to write them (most of the surveyed repositories use `f`, `d` and `m`), and none of these letters looks like a
  digit.

## Compared with StyleCop

StyleCop has no such rule. Sonar's S818 reports only `l` (and leaves `ul`); BRO1135 also upper-cases `u`.
`stylebro-migrate` turns it off (see [Rules beyond StyleCop](../differences-from-stylecop.md#rules-beyond-stylecop)).
