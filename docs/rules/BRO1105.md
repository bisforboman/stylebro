# BRO1105: Constructor initializers should be on their own line

Replaces StyleCop **SA1128**, with the same results.

Reports `: base(...)` or `: this(...)` that doesn't start its own line, including a colon at the end of the
constructor's line:

```csharp
public Pipeline(string name) : base(name)
{
}
```

## Code fix

Moves the initializer to the next line, one level deeper than the constructor:

```csharp
public Pipeline(string name)
    : base(name)
{
}
```

The indentation comes from `.editorconfig` (`indent_style`, `indent_size`, `tab_width`), and defaults to four spaces.
Everything after `base`/`this` stays as it is: the arguments, even when they span several lines, and a body on the
same line (`: base() { }`). A comment before the colon stays on the constructor's line.

## Not reported

- **An initializer that already starts its line.**
- **A primary constructor's base list** (`class D(int x) : B(x)`), which isn't a constructor initializer.
- **A comment between the colon and `base`/`this`** (`: /* note */ base()`). The fix rewrites exactly that stretch, so
  it would drop the comment.
