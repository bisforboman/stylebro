# BRO1002: Single-line comments should begin with a space

Replaces StyleCop **SA1005**, with the same results as StyleCop 1.2.

Reports `//` comments without a space after the slashes: `//note`, `M(); //trailing`, a tab after `//`.

## Code fix

Inserts a space: `//note` becomes `// note`. Tabs and other whitespace after `//` become a single space, and a
comment with nothing but whitespace becomes `//`. (StyleCop leaves a trailing space there.)

## Not reported

Like StyleCop:

- **Comments that already start with whitespace**, including `//  two spaces`. StyleCop 1.1.118 did report extra
  spaces; StyleCop 1.2 and StyleBro allow them, for indented text inside comments.
- **An empty comment** (`//`).
- **`///` and `////`**, which are used for commented-out code, and `///` documentation comments.
- **Separator lines starting with `//--`**, such as `//-----------`.
- **Text in inactive `#if` blocks**, which isn't a comment to the compiler.
