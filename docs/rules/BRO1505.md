# BRO1505: Elements should be separated by a blank line

Members, types and namespaces are separated by a blank line; consecutive fields may stay together. Replaces StyleCop
**SA1516**.

## Example

### Before

```csharp
using System;
namespace Shop
{
    public class Cart
    {
        private readonly decimal _vat = 0.25m;
        private decimal _net;
        public event EventHandler? Changed;
        public decimal Total => _net * (1 + _vat);
        public void Add(decimal price)
        {
            _net += price;
            Changed?.Invoke(this, EventArgs.Empty);
        }
        /// <summary>Empties the cart.</summary>
        public void Clear() => _net = 0;
    }
}
```

### After

```csharp
using System;

namespace Shop
{
    public class Cart
    {
        private readonly decimal _vat = 0.25m;
        private decimal _net;

        public event EventHandler? Changed;

        public decimal Total => _net * (1 + _vat);

        public void Add(decimal price)
        {
            _net += price;
            Changed?.Invoke(this, EventArgs.Empty);
        }

        /// <summary>Empties the cart.</summary>
        public void Clear() => _net = 0;
    }
}
```

## Why

Blank lines between members make the structure of a type visible at a glance, and let each member's comments and
attributes clearly belong to it. Fields are usually read together, so they may stay in one block.

## What is reported

An element that directly follows another element without a blank line in between:

- members of classes, structs, records and interfaces
- types and namespaces, and the first element after the using directives, assembly attributes or a file-scoped
  `namespace X;`
- accessors, when either of two neighbouring accessors spans several lines

A blank line anywhere between the two counts, also one between an element's comment or `#if` and its code. Like StyleCop,
these may stay together: two fields, two using directives, two extern aliases, two attribute lists,
and single-line accessors (`get { ... }` above `set { ... }`).

## How the fix works

The blank line goes above the element's first line: above its comments, XML docs and attributes, or above an `#if`
around it. Two members on one line are split, with a blank line between and the same indentation.

## Not reported

- **Two elements on one line with a comment between them.** The fix would have to move the comment.
- **Enum members**, which aren't elements in this sense.

## Compared with StyleCop

Same positions as StyleCop. StyleCop's fix leaves out the blank line above a `///` doc comment, and when it splits two
members on one line it leaves a trailing space and no indentation.
