# BRO1108: Parameters should be on the same line or on separate lines

Parameters and arguments are either all on one line or each on its own line. Replaces StyleCop **SA1117**.

## Example

### Before

```csharp
public class Mailer
{
    public void Send(string to, string subject,
        string body)
    {
    }

    public void Welcome(string to)
    {
        Send(
            to,
            "Welcome", "Thanks for signing up.");
    }
}
```

### After

```csharp
public class Mailer
{
    public void Send(
        string to,
        string subject,
        string body)
    {
    }

    public void Welcome(string to)
    {
        Send(
            to,
            "Welcome",
            "Thanks for signing up.");
    }
}
```

## Why

A list that is half on one line and half on separate lines is hard to scan: you can't tell at a glance how many items
there are or which is which. Either layout is fine; mixing them isn't.

## What is reported

Like StyleCop, the first two items decide which layout was meant:

- **The first two start on the same line:** every item has to start on that line. The first one that doesn't is
  reported.
- **The first two start on different lines:** no item may start on the line where the previous one ends. The first
  one that does is reported.

An item that spans several lines, like a lambda or a nested call, counts by the line it starts and ends on:
`M(1, 2, N(` then `3))` is fine, since `N(...)` starts on the first line. An empty `()` split over lines counts as joined
when [BRO1116](BRO1116.md) is on (its fix joins it): `N(` then `), M(5, 6)` is all on one line.

## How the fix works

Every item goes on its own line, starting on the line after the opening parenthesis, one level deeper than the line
with the parenthesis. The indentation comes from `.editorconfig` (`indent_style`, `indent_size`, `tab_width`) and
defaults to four spaces. Items that already start their line keep their indentation. A moved item's later lines (a
lambda's block body) move with it, by the same amount; a multi-line string inside keeps its lines.

The fix never joins lines: a list that spans lines because one item does can't be put on one line, and a list that
was split on purpose is usually long.

With `stylebro_split_list_first_item = same_line` (see [BRO1107](BRO1107.md#configuration)), a first item on the
opening parenthesis's line stays there, and the moved items are indented like the first item that already starts a
line (else one level deeper than the line with the parenthesis).

The lists checked are the same as for [BRO1107](BRO1107.md).

## Not reported

- **A comment or directive between the parenthesis and an item, or between items.** The fix rewrites exactly those
  gaps, so it would have to move or drop the comment.
- **Lists with syntax errors.**

## Compared with StyleCop

Same results as StyleCop, except that StyleCop 1.2.0-beta.556 doesn't check record parameters, primary-constructor
parameters or a primary constructor's base arguments. StyleCop has no working fix for SA1117; StyleBro's puts each
item on its own line, and moves a lambda's block body along with the lambda (StyleCop's fixes leave it behind:
[#1620](https://github.com/DotNetAnalyzers/StyleCopAnalyzers/issues/1620), [#3183](https://github.com/DotNetAnalyzers/StyleCopAnalyzers/issues/3183), open).
