# BRO1120: Comments should contain text

An empty comment at the start or end of a comment (or on its own) is removed. Replaces StyleCop **SA1120**.

## Example

### Before

```csharp
public class Report
{
    public int Total()
    {
        //
        // Sums the lines.
        //
        // Rounding happens later.
        //
        return 0;
    }
}
```

### After

```csharp
public class Report
{
    public int Total()
    {
        // Sums the lines.
        //
        // Rounding happens later.
        return 0;
    }
}
```

## Why

An empty comment is noise; inside a comment, an empty line separates paragraphs and stays.

## How the fix works

Comments on consecutive lines form a group. Like StyleCop, empty `//` or `/* */` comments are reported at the start and the end of a group; the fix removes every empty comment at that end, so one run is enough (StyleCop's fix removes one per run). A comment after code starts a new group, and `////` (commented-out code) isn't empty.

## Not reported

- **Empty lines in the middle of a comment**, which separate paragraphs.

## Compared with StyleCop

Same positions as StyleCop. StyleCop's fix removes only the reported comment, so a second empty one at the same end is reported on the next run.
