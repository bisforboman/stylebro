# BRO1103: Constants should be on the right-hand side of comparisons

Replaces StyleCop **SA1131**.

Reports comparisons (`==`, `!=`, `<`, `>`, `<=`, `>=`) with a constant on the left and a non-constant on the right:
`1 == x`, `null != o`, `0 < count`.

Like StyleCop, "constant" means literals, `null`, `default`, `const` fields, enum members, `nameof(...)`,
constant expressions such as `1 + 1`, and `static readonly` fields such as `string.Empty`.

## Code fix

Swaps the operands and flips relational operators: `0 < count` becomes `count > 0`, `Limit >= count` becomes
`count <= Limit`. Line breaks and comments stay where they are. `1 == 2 == b` becomes `b == (1 == 2)`, keeping its
meaning. Nested comparisons are fixed in one pass.

## Not reported

- **Comparisons that use a type's own operator**, such as `null == money` where `Money` defines `==`. A hand-written
  operator isn't guaranteed to give the same result with its operands reversed, and reversing them can even pick a
  different overload. StyleCop swaps these anyway. Operators from the .NET core library (`string`, `decimal`,
  `DateTime`, `Guid`, ...) are symmetric, so `Guid.Empty == id` is still reported.
- **Comparisons with a constant on both sides** (`1 == 2`), like StyleCop.
