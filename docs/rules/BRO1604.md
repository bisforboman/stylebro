# BRO1604: Property summary documentation should match accessors

A property's summary begins with the words its accessors call for: `Gets or sets`, `Gets` or `Sets`, followed by
`a value indicating whether` for a `bool`. Replaces StyleCop **SA1623**.

## Example

### Before

```csharp
public class Order
{
    /// <summary>The order number.</summary>
    public string Number { get; set; }

    /// <summary>Gets or sets the total.</summary>
    public decimal Total { get; }

    /// <summary>Whether the order is paid.</summary>
    public bool IsPaid { get; set; }
}
```

### After

```csharp
public class Order
{
    /// <summary>Gets or sets the order number.</summary>
    public string Number { get; set; }

    /// <summary>Gets the total.</summary>
    public decimal Total { get; }

    /// <summary>Gets or sets a value indicating whether the order is paid.</summary>
    public bool IsPaid { get; set; }
}
```

## Why

The summary then says at a glance what callers can do with the property, and it matches the .NET documentation.

## How the fix works

A wrong prefix is replaced, or the right one is added in front, with the next word's first letter lowered
(`The order number` becomes `Gets or sets the order number`; an acronym like `URL` keeps its capitals). For a
`bool`, a summary that starts with `Whether`, `Indicates whether` or `Gets whether` has that replaced too. The fix
doesn't rephrase anything else, so check summaries that started differently (`Is it closed` becomes
`Gets or sets a value indicating whether is it closed`).

Which words: `Gets or sets` for a getter and a setter other code can use, `Gets` for a getter only (a private or
internal setter doesn't count, see [BRO1605](BRO1605.md); a protected one does), `Sets` for a setter only.

This rule reads documentation as XML, which needs `<GenerateDocumentationFile>true</GenerateDocumentationFile>`.

## Not reported

- **Indexers, and properties with an `init` accessor.**
- **Summaries that start with an element** (`<see cref="..."/>`) or whose first words wrap to the next line.

## Compared with StyleCop

Same results as StyleCop. The fixed output differs only for `bool` summaries that start with `Whether` or
`Indicates whether`, where StyleCop keeps both (`a value indicating whether whether ...`).
