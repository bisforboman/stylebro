# BRO1504: Single-line comments should be preceded by a blank line

A `//` comment that follows code on the line above gets a blank line before it. Replaces StyleCop **SA1515**.

## Example

### Before

```csharp
public class Totals
{
    public decimal Sum(decimal[] amounts)
    {
        var sum = 0m;
        // Round each amount first, like the invoice does.
        foreach (var amount in amounts)
        {
            sum += decimal.Round(amount, 2);
        }
        // The caller adds VAT.
        return sum;
    }
}
```

### After

```csharp
public class Totals
{
    public decimal Sum(decimal[] amounts)
    {
        var sum = 0m;

        // Round each amount first, like the invoice does.
        foreach (var amount in amounts)
        {
            sum += decimal.Round(amount, 2);
        }

        // The caller adds VAT.
        return sum;
    }
}
```

## Why

A comment usually introduces the code below it. A blank line above makes clear which code it belongs to, and splits a
long method into readable steps.

## How the fix works

The fix inserts a blank line above the comment.

## Configuration

```ini
# Comments whose text starts with one of these (comma-separated, case-sensitive) need no blank line above.
# Default: none.
stylebro_comment_blank_line_exempt_prefixes = ReSharper, @formatter
```

Tool markers such as `// ReSharper disable once UnusedVariable` or `// @formatter:off` belong to the line below them
and aren't the start of a new step, so a blank line above them only pushes them away from the code they mark (StyleCop
issues [#3546](https://github.com/DotNetAnalyzers/StyleCopAnalyzers/issues/3546) and
[#1490](https://github.com/DotNetAnalyzers/StyleCopAnalyzers/issues/1490), where the only workaround is `////`). The
prefix is matched against the comment's text after `//` and any spaces, so `ReSharper` covers `// ReSharper disable`
and `//ReSharper restore`.

## Not reported

Like StyleCop:

- **The line above is blank, another comment, or a preprocessor directive.** A block of consecutive comment lines
  only needs one blank line, above the first.
- **The comment directly follows an opening brace** (the first line of a block), **the `[` of a collection expression,
  or a `case`/`default` label.**
- **The comment directly follows `=>`** (a switch expression arm, a lambda or an expression body): it starts what
  comes after the arrow, like a comment after `{`.
- **`////` commented-out code** and `///` comments.
- **Trailing comments** (`x++; // note`), which don't start their line.

Unlike StyleCop:

- **A comment below code**: a run of `//` lines right below a line that ends with `;`, followed by a blank line. It
  describes the code above it (eShop: a note below a field, then a blank line, then a method); moving the blank line
  above it would attach it to the code below. StyleCop reports it.

A comment after an ordinary `label:` is reported, like in StyleCop.

## Compared with StyleCop

Same results as StyleCop 1.2.0-beta.556, except a comment right after a collection expression's `[`: beta.556
reports it, StyleBro treats `[` like `{` (as StyleCop's unreleased fix for
[#3766](https://github.com/DotNetAnalyzers/StyleCopAnalyzers/issues/3766) does), and a comment right after `=>`:
StyleCop reports it and its fix puts a blank line between the arrow and the comment ([#3392](https://github.com/DotNetAnalyzers/StyleCopAnalyzers/issues/3392), open; for expression
bodies [#3550](https://github.com/DotNetAnalyzers/StyleCopAnalyzers/issues/3550)).
