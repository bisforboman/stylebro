# BRO1307: Field names should not begin with a prefix

Fields aren't named `m_count`, `s_count` or `t_count`. Replaces StyleCop **SA1308**.

## Example

### Before

```csharp
public class Session
{
    private static int s_opened;
    private readonly string m_user;

    public Session(string user)
    {
        m_user = user;
        s_opened++;
    }

    public string Describe() => m_user + " (" + s_opened + " open)";
}
```

### After

```csharp
public class Session
{
    private static int opened;
    private readonly string user;

    public Session(string user)
    {
        this.user = user;
        opened++;
    }

    public string Describe() => user + " (" + opened + " open)";
}
```

## Why

Hungarian-style prefixes repeat what the declaration already says (member, static, thread-static) and make names
harder to read.

The .NET runtime's own style does use `s_` for static fields and `t_` for thread-static fields. If you follow that
style, turn this rule off:

```ini
[*.cs]
dotnet_diagnostic.BRO1307.severity = none
```

## How the fix works

The field is renamed everywhere, and the new name is the complete correct name in one step: the prefix goes, any
underscores inside the name go ([BRO1308](BRO1308.md)), and the casing follows the field's kind: camelCase for private
fields (`_camelCase` if `stylebro_private_field_naming` says so, see [BRO1303](BRO1303.md)), PascalCase for constants,
`static readonly` and non-private fields ([BRO1306](BRO1306.md)), camelCase for protected fields. So `m_with_more`
becomes `withMore`, and `m_Upper` becomes `upper`. References that a local or parameter would hide are qualified
(`this.user`).

Only the lower-case prefixes `m_`, `s_` and `t_` count, like in StyleCop; other `x_` names are [BRO1308](BRO1308.md)'s.

## Not reported

- **A prefix your naming rules ask for**: when an active `dotnet_naming_rule` for fields uses a style with
  `required_prefix = s_` (the .NET runtime's convention for static fields), `s_` names are left alone.

- **Names that would be empty, a keyword or `field`** (`m_`, `s_static`, `m_field`; see [BRO1303](BRO1303.md)).
- The same unsafe cases as [BRO1303](BRO1303.md): a member with the new name, two fields getting the same name,
  attributes (a `t_` field usually has `[ThreadStatic]`, so it's left alone) or a `[Serializable]` type, the name in a
  string, in `#if`-excluded code, or as an inferred anonymous type member or tuple element name.

## Compared with StyleCop

Same fields, except the skipped cases above (StyleCop turns `s_static` into `@static`). StyleCop's fix only removes
the prefix (`m_Upper` becomes `Upper`, which then breaks SA1306), and `m_with_more` needs a second run for SA1310.
