# BRO1304: Interface names should begin with I

Interfaces are named `IShape`, not `Shape`. Replaces StyleCop **SA1302**.

## Example

### Before

```csharp
public interface Shape
{
    double Area();
}

public class Square : Shape
{
    public double Side { get; set; }

    public double Area() => Side * Side;

    public static double Total(Shape[] shapes)
    {
        double total = 0;
        foreach (Shape shape in shapes)
        {
            total += shape.Area();
        }

        return total;
    }
}
```

### After

```csharp
public interface IShape
{
    double Area();
}

public class Square : IShape
{
    public double Side { get; set; }

    public double Area() => Side * Side;

    public static double Total(IShape[] shapes)
    {
        double total = 0;
        foreach (IShape shape in shapes)
        {
            total += shape.Area();
        }

        return total;
    }
}
```

## Why

The `I` prefix is the .NET convention: it tells you at a glance that a type is a contract, not a class you can
create.

## How the fix works

The interface is renamed everywhere in the solution: declarations (every part of a partial interface), base lists,
types of variables and parameters, `typeof`, `nameof` and `cref` references. The new name is `I` plus the name with its
first letter capitalized: `Shape` becomes `IShape`, `iShape` becomes `IShape`, `_Shape` becomes `IShape`.

Like StyleCop, only the first letter is checked, so `Item` is a fine interface name.

**The file isn't renamed.** `dotnet format` only changes file contents, so `Shape.cs` keeps its name; rename it by
hand if you keep file names in sync with type names. **Renaming a public interface is a breaking change** for code
outside the solution.

## Not reported

- **The new name already means something:** a type with that name anywhere in the solution, or a member, type
  parameter or imported type with that name where the interface is declared.

## Reported but not fixed

- **The interface's name appears in a string** anywhere in the solution, alone or qualified (`"App.Shape"`,
  `"App.Shape, App"`): code can load types by name (`Type.GetType`, dependency injection, serializers), and the rename
  would still compile but fail at run time.
- **A reference somewhere else would see a different type with the new name**, for example a file with
  `using System.Collections;` that uses an interface `Enumerable` (it would become `IEnumerable`).

Rename these by hand, or suppress the warning.

## Compared with StyleCop

Same results as StyleCop. StyleCop's own fix changes nothing under `dotnet format`.
