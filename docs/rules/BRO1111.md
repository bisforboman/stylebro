# BRO1111: Generic type constraints should be on their own line

Each `where` clause starts its own line, one level deeper than the declaration. Replaces StyleCop **SA1127**.

## Example

### Before

```csharp
using System;
using System.Collections.Generic;

public class Cache<TKey, TValue> where TKey : IComparable<TKey> where TValue : class
{
    private readonly Dictionary<TKey, TValue> items = new Dictionary<TKey, TValue>();

    public TValue Get(TKey key) => items[key];

    public static TOut Convert<TOut>(TValue value) where TOut : class => value as TOut;
}
```

### After

```csharp
using System;
using System.Collections.Generic;

public class Cache<TKey, TValue>
    where TKey : IComparable<TKey>
    where TValue : class
{
    private readonly Dictionary<TKey, TValue> items = new Dictionary<TKey, TValue>();

    public TValue Get(TKey key) => items[key];

    public static TOut Convert<TOut>(TValue value)
        where TOut : class
        => value as TOut;
}
```

## Why

Constraints are part of the signature, but a long declaration with constraints at the end of the line hides them.
On their own lines, each constraint is easy to find and to change.

## How the fix works

Each `where` gets a new line, indented one level deeper than the line with the declaration's name. The indentation
comes from `.editorconfig` (`indent_style`, `indent_size`, `tab_width`) and defaults to four spaces. For an
expression-bodied member, the `=>` after the last constraint gets its own line too, like StyleCop's fix.

Checked: classes, structs, interfaces, records, methods, delegates and local functions.

## Not reported

- **A comment right before `where`** (`class Box<T> /* why */ where T : class`).

## Compared with StyleCop

Same results as StyleCop, with the same fixed output.
