# BRO1124: Refer to tuple elements by name

`item.Count` instead of `item.Item1` when the element has a name. Replaces StyleCop **SA1142**.

## Example

### Before

```csharp
public class Stock
{
    public (int Count, string Sku) Lookup() => (3, "A-1");

    public string Describe()
    {
        var item = Lookup();
        return item.Item2 + ": " + item.Item1;
    }
}
```

### After

```csharp
public class Stock
{
    public (int Count, string Sku) Lookup() => (3, "A-1");

    public string Describe()
    {
        var item = Lookup();
        return item.Sku + ": " + item.Count;
    }
}
```

## Why

The name says what the element is; `Item2` makes the reader look up the declaration.

## How the fix works

`ItemN` is replaced with the element's name, also after `?.` and for elements after the seventh (`Item8`).

## Not reported

- Elements without a name, `System.Tuple` (its `Item1` is a property, not a tuple element), and `nameof(t.Item1)`,
  whose result would change.

## Compared with StyleCop

Same positions, except `nameof(t.Item1)`. Under `dotnet format`, StyleCop's fix throws (a null reference), so it
changes nothing.
