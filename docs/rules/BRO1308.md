# BRO1308: Field names should not contain an underscore

Fields are named `maxValue` or `MaxValue`, not `max_value` or `MAX_VALUE`. Replaces StyleCop **SA1310**.

## Example

### Before

```csharp
public class Throttle
{
    public const int MAX_REQUESTS = 100;
    private int request_count;

    public bool TryEnter()
    {
        if (request_count >= MAX_REQUESTS)
        {
            return false;
        }

        request_count++;
        return true;
    }
}
```

### After

```csharp
public class Throttle
{
    public const int MaxRequests = 100;
    private int requestCount;

    public bool TryEnter()
    {
        if (requestCount >= MaxRequests)
        {
            return false;
        }

        requestCount++;
        return true;
    }
}
```

## Why

C# separates words by capital letters, not underscores. `MAX_REQUESTS` and `request_count` are habits from C and
other languages.

## How the fix works

The field is renamed everywhere. The words between the underscores are joined, and the casing follows the field's
kind: PascalCase for constants, `static readonly` and non-private fields ([BRO1306](BRO1306.md)), camelCase for private
fields (or `_camelCase`, see [BRO1303](BRO1303.md)) and protected fields. A word in all capitals counts as a word, not
an acronym: `MAX_REQUESTS` becomes `MaxRequests`, `request_count` becomes `requestCount`, `trailing_` becomes
`trailing`.

A leading underscore isn't this rule's business (it's [BRO1303](BRO1303.md)'s or [BRO1306](BRO1306.md)'s), and a
`m_`/`s_`/`t_` prefix is [BRO1307](BRO1307.md)'s, which also removes any underscores after it.

## Not reported

- **Names that would become a keyword.**
- The same unsafe cases as [BRO1303](BRO1303.md): a member with the new name, two fields getting the same name,
  attributes or a `[Serializable]` type, the name in a string (for public instance fields, anywhere inside a string,
  since serializers write them by name), in `#if`-excluded code, or as an inferred anonymous type member or tuple
  element name.

## Compared with StyleCop

Same fields as StyleCop. StyleCop's fix only deletes the underscores: `MAX_VALUE` becomes `MAXVALUE`.
