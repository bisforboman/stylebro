# BRO1401: Use a trailing comma in multi-line initializers

Replaces StyleCop **SA1413**.

Reports the last item of a multi-line list without a trailing comma. A trailing comma keeps diffs to one line when
items are added or reordered. Like StyleCop, the lists are:

- array, object and collection initializers (`new[] { ... }`, `new Point { ... }`, `new List<int> { ... }`)
- `with { ... }` expressions and anonymous objects
- enums and switch expressions

A list is multi-line when its braces are on different lines.

## Code fix

Inserts a comma right after the last item's code, so before a trailing comment: `2 // last` becomes `2, // last`.
When code follows the item directly (`"b"};`), the fix inserts `, ` so the comma gets the space after it that the
formatter expects. StyleCop's fix writes `"b",};` there.

Nested lists get all their commas in one `dotnet format` run.

## Not reported

- **Lists with a preprocessor directive between their braces**, such as an item inside `#if`. Which item is last
  then depends on the build configuration, and in a multi-targeted project each target framework would need a
  different edit to the same file. StyleCop reports them.
- **Collection expressions `[ ... ]`, list and property patterns**, and `{ key, value }` pairs in a dictionary
  initializer, like StyleCop 1.2.
