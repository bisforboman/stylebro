# BRO1126: Using directives should be qualified

A using directive inside a namespace names its namespace or type fully. Replaces StyleCop **SA1135**. Only relevant
when usings go inside the namespace (StyleCop's SA1200 default; the preset puts them outside).

## Example

### Before

```csharp
namespace System.Reporting
{
    using IO;
    using Builder = Text.StringBuilder;

    public class Export
    {
        public Builder Lines { get; } = new Builder();

        public FileInfo? Target { get; set; }
    }
}
```

### After

```csharp
namespace System.Reporting
{
    using System.IO;
    using Builder = System.Text.StringBuilder;

    public class Export
    {
        public Builder Lines { get; } = new Builder();

        public FileInfo? Target { get; set; }
    }
}
```

## Why

Inside a namespace, `using IO;` means something different depending on the namespace around it, so moving the code or
renaming the namespace can change what it refers to.

## How the fix works

The name is replaced with its fully qualified form, type arguments included (`int` stays `int`). `using static` and
aliases are checked too. An alias's own type stays a name (`System.ValueTuple<System.IO.Stream, int>`,
`System.Nullable<...>`, `System.Int32`): `(.., ..)`, `T?` and `int` there need C# 12. Inside type arguments the
shorthand is kept.

## Not reported

- Usings outside a namespace, names starting with `global::` or an alias, and a type of the namespace the directive
  is in (like StyleCop).
- **A type argument that starts with an alias** (`using T2 = System.ValueTuple<Tasks.Task, int>;` with
  `using Tasks = System.Threading.Tasks;` outside): it's kept as written, like an alias at the start of the name.
- **A qualified name that an enclosing namespace would hide**: inside `namespace Lib.Inner`, with a namespace
  `Lib.Inner.Lib` around, `Lib.Thing` would mean `Lib.Inner.Lib.Thing`.

## Compared with StyleCop

Same positions and output, except the hidden-name case above (StyleCop's fix then refers to the wrong namespace) and
a type argument that starts with an alias: StyleCop accepts `using T1 = Tasks.Task;` but reports
`using T2 = System.ValueTuple<Tasks.Task, int>;` ([#3884](https://github.com/DotNetAnalyzers/StyleCopAnalyzers/issues/3884), open).
