# BRO1607: Destructor summary documentation should begin with standard text

A finalizer's summary begins with `Finalizes an instance of the <see cref="T"/> class.`. Replaces StyleCop
**SA1643**.

## Example

### Before

```csharp
public class NativeBuffer
{
    /// <summary>Releases the native memory.</summary>
    ~NativeBuffer()
    {
    }
}
```

### After

```csharp
public class NativeBuffer
{
    /// <summary>Finalizes an instance of the <see cref="NativeBuffer"/> class. Releases the native memory.</summary>
    ~NativeBuffer()
    {
    }
}
```

## Why

The standard sentence is what the .NET documentation uses for finalizers, and it links to the type.

## How the fix works

Like [BRO1606](BRO1606.md): the standard sentence goes first, a near miss of it is replaced, and an empty or
whitespace-only summary gets it. This rule reads documentation as XML, which needs
`<GenerateDocumentationFile>true</GenerateDocumentationFile>`.

## Configuration

```ini
[*.cs]
# stylecop (default): StyleCop's SA1643, as described here.
# stylesharp: StyleSharp's SST1643 (bro migrate writes it for a StyleSharp repository; also BRO1604/BRO1605).
stylebro_summary_wording = stylecop
```

With `stylesharp` only the standard words before the type count: `Finalizes an instance of the Handle class.` is fine.

## Compared with StyleCop

Same results as StyleCop, including whitespace-only summaries. StyleCop's fix leaves out the space after the standard
sentence.
