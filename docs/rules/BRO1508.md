# BRO1508: A block should not be on a single line

A statement's block (`if`, `else`, loops, `using`, `lock`, `try`/`catch`/`finally`, a standalone `{ }`) puts its braces
and each statement on their own lines. Replaces StyleCop **SA1501**.

## Example

### Before

```csharp
public class Account
{
    public decimal Balance { get; private set; }

    public void Withdraw(decimal amount)
    {
        if (amount <= 0) { return; }
        if (amount > this.Balance) { throw new System.InvalidOperationException(); } else { this.Balance -= amount; }
    }
}
```

### After

```csharp
public class Account
{
    public decimal Balance { get; private set; }

    public void Withdraw(decimal amount)
    {
        if (amount <= 0)
        {
            return;
        }

        if (amount > this.Balance)
        {
            throw new System.InvalidOperationException();
        }
        else
        {
            this.Balance -= amount;
        }
    }
}
```

## Why

A one-line block hides control flow at the end of a line, and adding a second statement means reformatting the whole
block. Blocks laid out the same way everywhere are faster to scan.

## How the fix works

The braces get their own lines at the indentation of the statement, the statements inside go one level deeper (from
`indent_style`/`indent_size` in `.editorconfig`), and an empty block becomes `{` and `}` on two lines. `else`, `catch`
and `finally` that followed the `}` move to their own line. The fix only rewrites the spaces between those tokens, so
the code itself, a comment after the `}`, and the file's line endings stay as they are. Nested one-line blocks are
expanded in one pass. When [BRO1519](BRO1519.md) is on, a statement after the expanded block gets its blank line in
the same pass, and so does a statement inside that [BRO1514](BRO1514.md), [BRO1515](BRO1515.md) or
[BRO1516](BRO1516.md) wants braces on (`if (a) { if (b) return; }`): those rules leave the statements of a one-line
block to this fix, so one `dotnet format` run is enough.

The SDK's settings are respected: with `csharp_new_line_before_open_brace` not including `control_blocks`, the `{`
stays at the end of the statement's line (`if (x) {`), and `csharp_new_line_before_else = false` keeps `} else {`.
`do { ... } while (x);` keeps `while` after the `}`.

## Not reported

- **Lambda and anonymous-method bodies** (`() => { Run(); }`), like StyleCop.
- **A comment inside the braces** (`{ /* note */ return; }`): the fix would have to move it.
- **A block that shares its line with code that stays there**, like `case 1: { ... }` inside a
  `switch (x) { ... }` written on one line: there's no line to indent it from.
- Method and local function bodies are [BRO1509](BRO1509.md)'s.

## Compared with StyleCop

Same positions as StyleCop, except the cases under "Not reported" above. StyleCop's fix misindents nested blocks (it
writes `{` at the start of the line), moves `while` of `do ... while` to its own line, and writes Windows line endings
into files that use `\n`.
