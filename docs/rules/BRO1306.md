# BRO1306: Constant, static readonly and non-private field names should be PascalCase

Constants, `static readonly` fields and public or internal fields are named `MaxCount`, not `maxCount` or
`_maxCount`. Replaces StyleCop **SA1303**, **SA1311**, **SA1307** and **SA1304**.

## Example

### Before

```csharp
internal class Retry
{
    public const int maxAttempts = 3;
    private static readonly int[] delays = { 100, 500, 2000 };

    public int attempts;

    public int NextDelay() => attempts < maxAttempts ? delays[attempts++] : -1;
}
```

### After

```csharp
internal class Retry
{
    public const int MaxAttempts = 3;
    private static readonly int[] Delays = { 100, 500, 2000 };

    public int Attempts;

    public int NextDelay() => Attempts < MaxAttempts ? Delays[Attempts++] : -1;
}
```

## Why

Constants and `static readonly` fields act like fixed values of the type, and public fields are part of its surface
like properties, so they are named like properties. Private instance fields are camelCase instead
([BRO1303](BRO1303.md)).

## Configuration

Private constants and private `static readonly` fields can be camelCase instead (StyleCop issues
[#2641](https://github.com/DotNetAnalyzers/StyleCopAnalyzers/issues/2641) and
[#3793](https://github.com/DotNetAnalyzers/StyleCopAnalyzers/issues/3793)), when the SDK's naming rules ask for it, like
[BRO1303](BRO1303.md) follows them for private fields. The rule that counts is a `dotnet_naming_rule` whose symbols are
fields (kind `field` or `*`), private (accessibility `private` or `*`) and singled out by their modifiers: `const` (for
constants; `static` may be listed too), or `static` and/or `readonly` (for `static readonly` fields). Among those, the
lowest `priority` wins, then the rule with more required modifiers, then the name. If that rule's style is camel case
without a prefix, the fields are renamed to `maxAttempts`; with `required_prefix = _`, to `_maxAttempts`. Any other
style (PascalCase, an `s_` prefix) and no such rule leave the default, PascalCase. A naming rule without required
modifiers (all private fields) doesn't count: StyleCop and most teams name constants differently from fields.

```ini
[*.cs]
dotnet_naming_rule.private_constants.symbols = private_constants
dotnet_naming_rule.private_constants.style = camel
dotnet_naming_rule.private_constants.severity = warning
dotnet_naming_symbols.private_constants.applicable_kinds = field
dotnet_naming_symbols.private_constants.applicable_accessibilities = private
dotnet_naming_symbols.private_constants.required_modifiers = const
dotnet_naming_style.camel.capitalization = camel_case
```

Public, internal and protected constants stay PascalCase either way.

`stylebro_private_static_field_naming` sets the style of both directly and wins over the naming rules: `PascalCase`
(StyleCop's), `camelCase` or `_camelCase`. `stylebro-migrate --write` sets it to `PascalCase`, because StyleCop
enforced that whatever the naming rules said: a repository with a camel-case naming rule for static fields and IDE1006
turned off ("StyleCop handles these") keeps its `ProtocolVersion` fields.

```ini
[*.cs]
stylebro_private_static_field_naming = PascalCase
```

`stylebro_rename_public_api = true` also renames names other assemblies see (default `false`, see Not reported; the owner's decision in [decisions.md](https://github.com/bisforboman/stylebro/blob/main/docs/decisions.md)).

## How the fix works

The field is renamed everywhere in the solution. The new name drops leading underscores and capitalizes the first
letter: `maxAttempts` becomes `MaxAttempts`, `_minCount` becomes `MinCount`. Where a local or parameter with the new
name would hide the field, the reference is qualified (`Retry.MaxAttempts`, `this.Attempts`).

Checked: constants and `static readonly` fields of any accessibility, and public, internal and protected internal
fields. Protected fields are [BRO1303](BRO1303.md)'s, and enum members are left out (StyleCop's SA1300)
and one-letter prefixes like `s_count` (SA1308).

**Renaming a public field is a breaking change** for code outside the solution, and a serializer may write a public
field under its name (see below).

## Not reported

- **A non-private field whose name appears in code excluded by `#if` anywhere in the project** (private fields: in their type, see below): disabled code isn't compiled, so the rename can't follow it.
The same unsafe cases as [BRO1303](BRO1303.md): a member with the new name in the type or a base type, two fields that
would get the same name, attributes or a `[Serializable]` type, the old name in a string in the type (for public
instance fields, anywhere inside a string, like a JSON example), in `#if`-excluded code, or as an inferred anonymous
type member or tuple element name, and fields of a type with a generated part (a Razor component's code-behind class).

## Reported but not fixed

**If `dotnet format` leaves a finding, StyleBro kept it on purpose.** The fix looks at the whole solution, other
projects included, which the analyzer can't see, and leaves a change that would break something there: the name in a
string or a `nameof` (reflection, serialization), a member that would hide it, a use in generated code. It offers no
code action for such a finding, and `stylebro-migrate format` lists each one with its reason
([Findings kept on purpose](../getting-started.md#findings-kept-on-purpose)); its `--verify-no-changes` doesn't fail on
them. Change it by hand only after checking those uses, or suppress it or record it in the [baseline](../baseline.md).

- **Public API** (unless `stylebro_rename_public_api = true`): Fields that other assemblies see, that is public, protected or protected internal in types that are visible too. Renaming them breaks code outside the solution. Internal code is renamed, also with `InternalsVisibleTo`.
- **A name that `nameof(...)` produces**: the rename would change the string (Ocelot built an HTTP header name with `nameof(X_RateLimit_Limit)`, and a test read a private field with `GetField(nameof(_components))`). Looked for in the member for variables and parameters, in the type for fields; the fix also looks in the rest of the solution and leaves the warning when it finds one.
- **The old name appears in a string anywhere in the solution.** For a public or internal instance field that includes
  appearing inside a longer string, like test JSON (`"{\"attempts\": 1}"`): serializers such as Json.NET write public
  fields under their name, so the rename would change the output.
- **Some reference would see another member with the new name**, for example a property `MaxAttempts` in a derived
  class, which would hide the renamed field there.
- **Generated code uses the field** (a source generator's output, a `.g.cs` file), or its name is a string there.

Rename these by hand, or suppress the warning.

## Compared with StyleCop

Same fields as StyleCop, with one diagnostic per field where StyleCop can report two (SA1307 with SA1311 or SA1304).
A constant or `static readonly` field that starts with `_` is renamed too (`_minCount` becomes `MinCount`); StyleCop
leaves that one to SA1309.
