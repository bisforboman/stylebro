# BRO1112: Do not use regions

`#region` isn't used between members or types. Replaces StyleCop **SA1124**. Regions inside a member's body are
[BRO1113](BRO1113.md).

## Example

### Before

```csharp
public class Account
{
    #region Fields

    private decimal balance;

    #endregion

    #region Methods

    public void Deposit(decimal amount)
    {
        balance += amount;
    }

    #endregion
}
```

### After

```csharp
public class Account
{
    private decimal balance;

    public void Deposit(decimal amount)
    {
        balance += amount;
    }
}
```

## Why

Regions hide code instead of organizing it: a class that needs them to be readable is usually doing too much, and
collapsed regions make reviewers miss what's inside. Member ordering ([BRO1001](BRO1001.md)) already groups members
by kind.

StyleCop has SA1124 turned off by default, and so does StyleBro's preset. Turn it on to remove regions:

```ini
[*.cs]
dotnet_diagnostic.BRO1112.severity = warning
```

## How the fix works

The `#region` and `#endregion` lines are removed. A blank line next to them goes too when it would otherwise double
another blank line, follow an opening brace or precede a closing brace. Directives inside the region (`#if`) stay.

**Removing regions can make [BRO1001](BRO1001.md) report the type:** member ordering skips types with regions, so
it only sees them once they're gone. The next `dotnet format` run sorts them.

## Compared with StyleCop

Same results as StyleCop, with the same fixed output.
