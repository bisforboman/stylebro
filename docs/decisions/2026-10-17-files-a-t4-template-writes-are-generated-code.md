# Files a T4 template writes are generated code (2026-10-17)

## Question

Trial 28 (ZLogger): `MessageTemplate.Format.cs`, `ZLoggerExtensions.cs` and `ZLoggerInterpolatedStringHandler.LogLevel.cs`
are written by T4 templates (`.tt` files beside them; the project lists them with `<DependentUpon>*.tt</DependentUpon>`
and `<AutoGen>True</AutoGen>`). They have no `<auto-generated>` header, so Roslyn treats them as hand-written code:
StyleBro reported them in the build and `format` rewrote them, and the next run of the template undoes that. Should they
count as generated code?

## Choices

1. Yes, as generated: no StyleBro findings in the build, and `format` leaves them alone.
2. No: they're in the repository and compiled like any other file.

## Decision

**Choice 1: Yes, as generated** (owner's choice, 2026-10-17). The package's build targets add every Compile item with
`DependentUpon` ending in `.tt` or `AutoGen` True to the list `GeneratedFileSuppressor` reads (`StyleBroGeneratedFolders`),
so StyleBro doesn't analyze them, and the built-in rules' findings the preset and `init` turn on are hidden there too.
`stylebro-migrate format` excludes the C# file next to each `.tt` file with the same name. They aren't marked
`generated_code = true` for the compiler: that would also change their nullable context (generated code starts with
`#nullable disable`), which can add warnings to a build.
