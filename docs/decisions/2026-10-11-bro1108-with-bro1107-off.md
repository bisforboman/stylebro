# BRO1108 with BRO1107 off (2026-10-11)

## Question

`stylebro-migrate init` turns BRO1107 off when a repository splits lists both ways (first item after `(` and first item
on the next line). BRO1108's "each item on its own line" fix still moved the first item to the next line
(realworlddotnet: `UpdateBySlugAsync(string slug,` became `UpdateBySlugAsync(` + `string slug,`), doing BRO1107's job
although that rule is off. What should BRO1108's fix do with the first item then?

## Choices

1. **Keep the first item where it is**: with BRO1107 off, BRO1108's fix behaves like `stylebro_split_list_first_item =
   same_line`; the other items go on their own lines, indented like the first item of the list that already starts a
   line (aligned under the first item, or one level deeper), else one level deeper than the line with `(`.
2. Keep moving the first item (BRO1108's fix is the full "each on its own line" layout).
3. Have `init` write `same_line` instead of turning BRO1107 off.

## Decision

**Choice 1** (owner: "Keep the first item where it is"). One check (`ParameterLayout.KeepsFirstItem`: `same_line`, or
BRO1107 off per `Severities.IsOn`) used by BRO1108's fix and by the same-line joins that reuse it. The indentation is
the existing `same_line` logic, so a list keeps whichever form it already uses for its later lines.
